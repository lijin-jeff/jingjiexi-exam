# 分析进入答题页面点击答题卡第一题题号变成24的原因

## 问题描述
用户进入答题页面（第1题）后，点击答题卡按钮，第一题题号会变成24。

## 根本原因

### 核心问题
**simplifiedQuestionList 与 swiperList 的 UID 映射错误**

1. **执行流程分析**：
   - 用户进入答题页面，显示第1题，`swiperCurrentIndex` 为 0
   - 点击答题卡按钮，`handleShowAnswerCard` 方法执行
   - `handleShowAnswerCard` 方法调用 `getQuestionStructure` 获取题目结构
   - `getQuestionStructure` 调用 API 返回题目列表 A，构建 `simplifiedQuestionList`
   - 同时，`swiperList` 加载完成，包含题目列表 B
   - `displayQuestionIndex` 计算属性重新计算：
     - 获取 `swiperList[0]`（第1题）的 UID
     - 在 `simplifiedQuestionList`（基于题目列表 A）中查找该 UID
     - 找到该 UID 在 `simplifiedQuestionList` 中的索引为 23
     - 返回 23，显示的题号变为 24

2. **技术细节**：
   - `displayQuestionIndex` 计算属性的实现：
     ```javascript
     displayQuestionIndex() {
       if (this._clickedQuestionIndex !== -1) {
         return this._clickedQuestionIndex;
       }
       if (this.simplifiedQuestionList && this.simplifiedQuestionList.length > 0) {
         const currentQuestion = this.swiperList[this.swiperCurrentIndex];
         if (currentQuestion && currentQuestion.uid) {
           const index = this.simplifiedQuestionList.findIndex(item => item.uid === currentQuestion.uid);
           if (index !== -1) {
             return index;
           }
         }
       }
       return this.swiperCurrentIndex;
     }
     ```

   - `getQuestionStructure` 方法的实现（关键问题）：
     - 第 1230-1234 行被注释掉，导致即使 `swiperList` 不为空，也总是调用 API 获取题目结构
     - 这可能导致返回的题目列表 A 与 `swiperList` 中的题目列表 B 顺序不同

## 修复方案

### 1. 恢复 getQuestionStructure 方法的原逻辑

- **修改内容**：取消注释 `getQuestionStructure` 方法的第 1230-1234 行
- **修改原因**：确保当 `swiperList` 不为空时，直接使用 `swiperList` 构建 `simplifiedQuestionList`，避免 UID 映射错误
- **预期效果**：点击答题卡按钮时，`simplifiedQuestionList` 使用 `swiperList` 中的数据构建，与 `swiperList` 的 UID 顺序一致，避免题号错误

### 2. 优化 displayQuestionIndex 计算属性

- **修改内容**：修改 `displayQuestionIndex` 计算属性的逻辑，优先使用 `swiperCurrentIndex`，只有在特定情况下才使用 `simplifiedQuestionList` 的索引
- **修改原因**：确保显示的题号与 `swiperList` 中的索引一致，避免 UID 映射错误导致的题号变化
- **预期效果**：点击答题卡按钮后，显示的题号保持与 `swiperList` 中的索引一致，不会因为 `simplifiedQuestionList` 的变化而改变

### 3. 同步题目加载和显示

- **修改内容**：在 `handleShowAnswerCard` 方法中，等待 `swiperList` 加载完成后再构建 `simplifiedQuestionList`
- **修改原因**：确保 `simplifiedQuestionList` 与 `swiperList` 基于相同的题目数据构建，避免 UID 映射错误
- **预期效果**：点击答题卡按钮后，`simplifiedQuestionList` 与 `swiperList` 基于相同的题目数据构建，避免题号错误

## 推荐方案

**方案 1：恢复 getQuestionStructure 方法的原逻辑**

- **推荐理由**：这是最直接、最根本的解决方案，能从源头上避免 UID 映射错误的问题
- **实现简单**：只需取消注释 `getQuestionStructure` 方法的第 1230-1234 行
- **风险最小**：不会影响其他功能，只是恢复了原有的正确逻辑

**方案 2 作为备选方案**：如果方案 1 无法解决问题，可以考虑方案 2

通过实施推荐方案，用户进入答题页面后，点击答题卡按钮，第一题题号将保持为 1，不会变成 24。
