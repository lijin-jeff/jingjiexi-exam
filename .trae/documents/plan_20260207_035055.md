# 修复option字段返回为空的问题

## 问题分析

用户反馈修改后 `option: []` 返回为空，实际上 option 是不为空的，以前有数据返回，修改后没了。

### 可能的原因

1. **option字段解码问题**：
   - option字段在数据库中可能是JSON字符串格式
   - 修改后的代码没有对option字段进行解码
   - 导致 `isset($item['option']) && is_array($item['option'])` 返回false
   - 最终 `item['option']` 被设置为空数组

2. **查询条件问题**：
   - 修改后的查询条件可能导致返回的题目数据不完整
   - 但这种可能性较小，因为其他字段应该也会受到影响

## 解决方案

修改 `orderOptionList` 方法，添加对 `option` 字段的解码逻辑，确保即使 `option` 字段是 JSON 字符串格式，也能被正确解码为数组。

### 具体修改

1. **在处理option字段时添加解码逻辑**：
   - 检查 `item['option']` 是否存在
   - 如果存在且是字符串，尝试解码为数组
   - 然后再检查解码后的结果是否是数组
   - 最后为每个选项设置 `is_selected` 和 `status` 属性

### 预期结果

- 修改后 `option` 字段能够正确返回数据
- 即使 `option` 字段在数据库中是 JSON 字符串格式，也能被正确解码为数组
- 保持与修改前相同的行为，确保前端能够正确显示选项数据
