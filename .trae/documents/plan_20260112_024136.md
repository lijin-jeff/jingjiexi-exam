## 问题分析

1. **问题现象**：跳转部分页面需要登录时，会打开多个登录页面。

2. **问题原因**：
   - 当用户访问需要登录的页面时，页面会发起API请求
   - API请求失败返回401未授权状态
   - 请求拦截器捕获401状态，调用uni.navigateTo跳转登录页面
   - 如果页面同时发起多个API请求，每个请求都会触发401处理逻辑
   - 导致多次调用uni.navigateTo，打开多个登录页面

3. **关键代码**：
   - `request.js`第58-60行：401状态处理，直接调用`uni.navigateTo({ url: '/subpages/user/login' })`
   - `userStore.js`第231-241行：`navigateToLogin`函数，直接调用`uni.navigateTo({ url })`
   - `userStore.js`第249-276行：`ensureUserLoggedIn`函数，调用`navigateToLogin`跳转登录页面

## 解决方案

1. **防止重复跳转**：在跳转到登录页面之前，检查当前页面栈中是否已经存在登录页面
2. **统一跳转方式**：使用uni.redirectTo代替uni.navigateTo，避免页面栈堆积
3. **添加跳转锁**：添加一个全局锁，防止短时间内多次跳转

## 修复方案

1. **修改request.js**：
   - 在401状态处理时，检查页面栈，避免重复跳转
   - 使用uni.redirectTo代替uni.navigateTo

2. **修改userStore.js**：
   - 在navigateToLogin函数中，检查页面栈，避免重复跳转
   - 使用uni.redirectTo代替uni.navigateTo

2. **修改userStore.js**：
```javascript
/**
 * 跳转到登录页面
 * @param {string} redirectUrl - 登录成功后的跳转地址
 */
export function navigateToLogin(redirectUrl = '') {
    try {
        let url = '/subpages/user/login';
        if (redirectUrl) {
            url += `?redirect=${encodeURIComponent(redirectUrl)}`;
        }
        
        // 检查页面栈，避免重复跳转
        const pages = getCurrentPages();
        const loginPageIndex = pages.findIndex(page => page.route === 'subpages/user/login');
        if (loginPageIndex === -1) {
            uni.redirectTo({ url });
        }
    } catch (error) {
        console.error('跳转登录页失败:', error);
    }
}
```
