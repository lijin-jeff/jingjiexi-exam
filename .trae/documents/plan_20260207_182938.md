## 问题分析

### 问题1：57题滑动到56题，一次跳了2题（实际题目是55题）

**根本原因**：`activeQuestions` 构建时，`prevQ` 查找失败，导致使用 `currQ` 作为占位符。

从日志：
- `activeQuestionsUids: "0:697b660f671dd, 1:697b660f671dd, 2:697b2a9f98ffd"`
- 索引0和索引1都是同一个uid（56题）

这意味着 `swiperList` 中没有55题，所以 `prevQ` 查找失败。

**解决方案**：
1. 修改 `activeQuestions` 构建逻辑，当 `prevQ` 查找失败时，尝试从 `simplifiedQuestionList` 中获取上一题的 uid，然后异步加载
2. 或者修改 `handleSwiperChange`，当滑动到边界且 `activeQuestions[swiperIndex]` 和当前题相同时，先加载上一块题目，然后再更新索引

### 问题2：加载上一个题块后，向左滑动跳转到41题而不是49题

**根本原因**：`loadPreviousChunkIfNeeded` 加载新题块后，`swiperCurrentIndex` 没有正确更新。

从日志：
- 新题目插入到索引40-49（10道题：41-50题）
- 但用户跳转到了41题（第5块的第一个题），而不是49题（第5块的最后一个题）

**解决方案**：
1. 修改 `loadPreviousChunkIfNeeded`，加载完成后，更新 `swiperCurrentIndex` 到正确的位置（上一块的最后一个题）
2. 或者修改 `fetchQuestionList`，在合并题目列表后，保持当前题目的索引不变

## 修复计划

### 1. 修复 `activeQuestions` 构建逻辑

当 `prevQ` 查找失败时，尝试从 `simplifiedQuestionList` 中获取上一题的 uid，然后触发异步加载：

```javascript
activeQuestions() {
  // ... 获取 prevQ, currQ, nextQ
  
  // 如果 prevQ 查找失败，但 simplifiedQuestionList 中有上一题，触发异步加载
  if (!prevQ && this.simplifiedQuestionList && currentQuestionNum > 0) {
    const prevQuestionNum = currentQuestionNum - 1;
    const prevUid = this.simplifiedQuestionList[prevQuestionNum]?.uid;
    if (prevUid) {
      // 触发异步加载上一块
      this.$nextTick(() => {
        this.loadPreviousChunkIfNeeded();
      });
    }
  }
  
  // ... 构建 questions 数组
}
```

### 2. 修复 `loadPreviousChunkIfNeeded`

加载完成后，更新 `swiperCurrentIndex` 到正确的位置：

```javascript
async loadPreviousChunkIfNeeded() {
  // ... 加载上一块
  
  // 加载完成后，更新 swiperCurrentIndex 到上一块的最后一个题
  const targetIndex = (previousChunkIndex + 1) * chunkSize - 1; // 上一块的最后一个题
  const targetUid = this.simplifiedQuestionList[targetIndex]?.uid;
  if (targetUid) {
    const newIndex = this.swiperList.findIndex(item => item.uid === targetUid);
    if (newIndex !== -1) {
      this.swiperCurrentIndex = newIndex;
    }
  }
}
```

### 3. 修复 `handleSwiperChange`

当滑动到边界且需要加载新题块时，等待加载完成后再更新索引：
