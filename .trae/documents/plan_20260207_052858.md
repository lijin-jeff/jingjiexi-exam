# 修复orderOptionList和getQuestionStructure返回数据不一致的问题

## 问题分析
通过分析代码，发现了导致两个方法返回数据不一致的根本原因：

1. **参数处理差异**：
   - 两个方法都使用 `prepareQuestionQuery` 处理参数，但在调用时机和上下文上存在差异
   - 当按比例获取题目时，对每种题型单独调用 `prepareQuestionQuery`，可能导致不同的查询结果

2. **排序逻辑不完整**：
   - 非随机模式下，两个方法都只按题型排序：`usort($items, function ($a, $b) { return $a['exam_type'] <=> $b['exam_type']; });`
   - 这种排序方式会丢失同题型内的原始顺序

3. **数据处理时机**：
   - 两个方法在处理数据的时机和方式上存在细微差异
   - 可能导致相同参数下返回不同顺序的数据

## 实现计划

### 1. 统一排序逻辑
- 修改两个方法的排序逻辑，确保非随机模式下既按题型排序，又按sort字段排序
- 使用更完整的排序函数：
  ```php
  usort($items, function ($a, $b) {
    // 先按题型排序
    if ($a['exam_type'] != $b['exam_type']) {
      return $a['exam_type'] <=> $b['exam_type'];
    }
    // 再按sort字段排序
    return ($b['sort'] ?? 0) <=> ($a['sort'] ?? 0);
  });
  ```

### 2. 确保参数一致性
- 确保两个方法在调用 `prepareQuestionQuery` 时传递完全相同的参数
- 特别是在按比例获取题目时，确保每种题型的参数处理一致

### 3. 统一数据处理流程
- 确保两个方法的数据处理流程完全一致
- 包括查询构建、排序、offset和limit应用等步骤

### 4. 测试和验证
- 测试两个方法在相同参数下返回的数据是否一致
- 验证不同offset和limit参数下的返回结果
- 确保边界情况的正确处理

## 技术要点
- 确保排序逻辑的完整性，避免丢失同题型内的顺序
- 确保参数处理的一致性，避免相同参数下返回不同结果
- 确保数据处理流程的统一性，提高代码的可维护性
- 验证修复后的结果，确保两个方法返回一致的数据
