## 问题分析

**现象**：打开答题卡，点击跳转57题，然后跳转到56题。

**根本原因**：
1. **handleSwiperChange方法的逻辑问题**：虽然添加了对`needProgrammaticJump`的检查，但在某些情况下可能没有正确生效，导致动画完成后重新计算`newRealIndex`，跳转到错误的题目。

2. **currentQuestion计算属性的安全索引问题**：当`localQuestionList`长度小于`swiperCurrentIndex`时，会使用`safeIndex: Math.min(currentIndex, this.localQuestionList.length - 1)`，这可能导致返回错误的题目。

3. **activeQuestions计算逻辑**：当跳转到索引56（对应57题）时，`activeQuestions`计算属性返回的是从索引55到56的题目，即包含56题和57题，可能导致显示错误。

## 解决方案

### 1. 修改handleSwiperChange方法
- **增强对程序化跳转的判断**：确保在`needProgrammaticJump`为`true`时，完全跳过程序化跳转的处理逻辑，不修改任何状态
- **优化状态重置逻辑**：确保只在非程序化跳转时重置状态

### 2. 优化currentQuestion计算属性
- **调整数据来源优先级**：优先从`swiperList`获取题目，而不是从`localQuestionList`获取
- **改进安全索引计算**：确保即使在`localQuestionList`长度不足时，也能从`swiperList`获取正确的题目
- **增强容错处理**：添加多层容错处理，确保在各种情况下都能返回有效的题目

### 3. 优化handleQuestionChange方法
- **增强跳转逻辑**：确保在设置`needProgrammaticJump`后，能正确处理题目跳转
- **优化延迟时间**：确保`needProgrammaticJump`的延迟重置时间足够长，确保动画完全完成
- **添加强制更新**：确保在设置跳转标志后，组件状态能及时更新

### 修改2：优化currentQuestion计算属性
```javascript
// 当前题目计算属性
currentQuestion() {
  // 首先尝试从swiperList获取，因为swiperList是完整的题目列表
  const currentIndex = this.swiperCurrentIndex;
  const safeIndex = Math.max(0, Math.min(currentIndex, this.swiperList.length - 1));
  let question = this.swiperList[safeIndex] || {};
  
  // 验证题目有效性
  if (!question.uid && this.swiperList.length > 0) {
    // 遍历查找第一个有效的题目
    for (let i = 0; i < this.swiperList.length; i++) {
      const item = this.swiperList[i];
      if (item && item.uid) {
        question = item;
        break;
      }
    }
  }
  
  // 如果swiperList中没有找到有效的题目，再尝试从localQuestionList获取
  if (!question.uid && this.localQuestionList.length > 0) {
    const localSafeIndex = Math.max(0, Math.min(currentIndex, this.localQuestionList.length - 1));
    question = this.localQuestionList[localSafeIndex] || {};
  }
  
  return question;
}
```
