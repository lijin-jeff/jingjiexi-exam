# 优化答题页面初始化流程

## 问题分析

当前答题页面的初始化流程是：
1. 进入页面后直接调用 `fetchQuestionList` 加载第一块题目（前10题）
2. 当用户点击显示答题卡时，才调用 `getQuestionStructure` 获取题目结构信息
3. 这种方式可能导致：
   - 答题卡显示延迟
   - 题目结构信息不完整
   - API 调用冗余

## 优化方案

### 1. 调整初始化流程
- 修改组件的初始化逻辑，在页面加载时先调用 `getQuestionStructure` 获取完整的题目结构信息
- 在 `getQuestionStructure` 成功后，再调用 `fetchQuestionList` 加载第一块题目

### 2. 确保数据传递正确
- 确保 `getQuestionStructure` 成功后，将返回的题目结构信息存储到 `simplifiedQuestionList` 中
- 确保 `fetchQuestionList` 能够正确使用 `simplifiedQuestionList` 中的题目 UID 信息
- 优化 `buildApiParams` 方法，确保在有题目结构信息时正确构建 `question_uids` 参数

### 3. 处理异常情况
- 实现 `getQuestionStructure` 失败的降级方案，确保即使题目结构信息获取失败，也能正常加载题目
- 优化加载状态的显示，确保用户体验良好

### 4. 具体修改点
- 修改组件的 `mounted` 或 `created` 生命周期钩子，调整初始化流程
- 优化 `getQuestionStructure` 方法的缓存机制，确保数据的一致性
- 调整 `fetchQuestionList` 方法的调用时机，确保在获取题目结构信息后再调用

## 预期效果

1. **提升用户体验**：用户一进入页面就能看到完整的答题卡结构
2. **减少 API 调用**：避免重复请求相同的数据
3. **确保数据一致性**：确保 `getQuestionStructure` 和 `fetchQuestionList` 返回的数据顺序一致
4. **提高加载效率**：通过合理的请求顺序，减少不必要的 API 调用

## 技术实现要点

- 使用 Promise 链式调用确保请求顺序
- 实现合理的错误处理机制
- 优化加载状态的显示
- 确保缓存机制的正常工作
