# 优化答题卡显示全部题号的逻辑

## 问题分析

当前实现中，`getQuestionStructure` 方法优先使用 `swiperList` 中的数据构建 `simplifiedQuestionList`。当 `swiperList` 每次只请求10个题目时，`simplifiedQuestionList` 也只会包含10个题目，导致答题卡只显示10个题号，而不是全部题号。

## 优化方案

修改 `getQuestionStructure` 方法，确保即使 `swiperList` 只包含部分题目，答题卡也能显示全部题号：

1. **始终调用 API 获取完整的题目结构信息**：
   - 不再优先使用 `swiperList` 中的数据
   - 确保 `simplifiedQuestionList` 包含全部题目，答题卡显示全部题号

2. **保留使用本地数据填充状态**：
   - 在获取完整题目结构信息后，使用 `swiperList` 中的数据来填充已加载题目的状态（如是否已答、用户答案等）
   - 这样既可以显示全部题号，又可以保持已加载题目的状态

3. **添加缓存机制**：
   - 缓存 API 返回的完整题目结构信息
   - 这样在后续打开答题卡时，就不需要重复调用 API，提高性能

## 预期效果

- 答题卡显示全部题号，即使 `swiperList` 只包含部分题目
- 已加载题目的状态（如是否已答、用户答案等）保持正确
- 性能得到优化，避免重复的 API 调用
- 用户体验得到改善，答题卡显示完整的题目信息
