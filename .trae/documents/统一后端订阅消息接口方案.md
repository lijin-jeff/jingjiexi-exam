# 统一后端订阅消息接口方案

## 1. 问题分析

当前后端存在两个独立的订阅接口：

* **模板订阅接口**：`IndexLogic::templateSubscribe` - 用于版本更新订阅

* **倒计时订阅接口**：`CountdownLogic::follow` - 用于倒计时订阅

这两个接口功能相似但实现不同，导致：

* 代码冗余，维护成本高

* 数据模型不统一，增加复杂度

* 前端调用方式不一致

## 2. 统一方案设计

### 2.1 核心设计思路

* 创建**统一的订阅控制器和逻辑类**

* 支持**多种订阅类型**：版本更新、倒计时等

* 设计**通用的数据模型**

* 保持**与现有前端调用兼容**

* 统一**微信发送订阅消息的逻辑**

#### 2.2.1 统一订阅接口

// 统一订阅/取消订阅接口

### 2.3 核心实现

#### 2.3.1 统一订阅控制器

```php
namespace app\api\controller;

class SubscribeController extends BaseApiController
{
    /**
     * 统一订阅/取消订阅
     */
    public function subscribe()
    {
        $params = $this->request->post();
        $params['user_id'] = $this->userId;
        $result = SubscribeLogic::subscribe($params);
        return $result['success'] ? $this->success($result['msg']) : $this->fail($result['msg']);
    }
}
```

#### 2.3.2 统一订阅逻辑类

```php
namespace app\api\logic;

class SubscribeLogic extends BaseLogic
{
    /**
     * 统一订阅/取消订阅逻辑
     */
    public static function subscribe(array $params)
    {
        $type = $params['type'] ?? '';
        $relatedId = $params['related_id'] ?? 0;
        $subscribeStatus = $params['subscribe_status'] ?? 1;
        $userId = $params['user_id'] ?? 0;
        
        // 根据不同类型处理订阅
        switch ($type) {
            case 'countdown':
                // 倒计时订阅逻辑
                return self::handleCountdownSubscribe($params);
            case 'version_update':
                // 版本更新订阅逻辑
                return self::handleVersionUpdateSubscribe($params);
            default:
                return ['success' => false, 'msg' => '未知的订阅类型'];
        }
    }
    
    /**
     * 处理倒计时订阅
     */
    private static function handleCountdownSubscribe(array $params)
    {
        // 复用现有CountdownLogic::follow逻辑
        return CountdownLogic::follow($params);
    }
    
    /**
     * 处理版本更新订阅
     */
    private static function handleVersionUpdateSubscribe(array $params)
    {
        // 复用现有templateSubscribe逻辑
        return IndexLogic::templateSubscribe($params);
    }
}
```

### 2.4 数据模型设计

## 3. 实现步骤

1. **创建统一订阅控制器**：`app/api/controller/SubscribeController.php`
2. **创建统一订阅逻辑类**：`app/api/logic/SubscribeLogic.php`
3. **添加统一订阅路由**：在路由文件中添加新路由
4. **修改现有逻辑类**：让CountdownLogic和IndexLogic调用统一方法
5. **更新数据模型**：创建统一的订阅表（可选，可先保持现有表结构）
6. **统一微信发送逻辑**：优化WeChatMnpService
7. **测试验证**：确保现有功能正常工作

## 4. 预期效果

* ✅ **代码统一**：减少冗余，提高可维护性

* ✅ **接口统一**：前端调用方式一致

* ✅ **数据模型统一**：便于扩展新的订阅类型

* ✅ **兼容现有功能**：不破坏现有前端调用

* **模块化设计**：订阅逻辑集中管理

* **类型驱动**：支持多种订阅类型

* **统一的错误处理**：一致的错误码和错误信息
