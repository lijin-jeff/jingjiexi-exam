## 问题分析

通过分析 `commonQuestion.vue` 文件，我发现了两个导致题目显示和切换问题的根本原因：

### 1. 首次进入会跳到第二题
- **原因**：`virtualCurrentIndex` 计算属性始终返回1，而 `swiper` 组件的 `:current` 属性绑定到这个值
- **影响**：当 `swiperCurrentIndex` 初始化为0时，虚拟列表会包含题目0、1、2，而 `swiper` 会显示索引1的题目（第二题）
- **结果**：进度条显示1/37，但实际显示的是第二题

### 2. 切换下一题时，题目序号不会变化
- **原因**：所有题型组件的 `:question-index` 绑定的是虚拟列表的相对索引 `index`（0、1、2）
- **影响**：无论真实题目是第几题，显示的序号始终是虚拟列表中的相对位置
- **结果**：切换题目时，题目序号可能不会正确更新

### 3. 其他相关问题
- 案例题的 `:is-last-question` 判断基于虚拟列表索引，而不是真实索引
- 虚拟列表边界处理可能存在问题

## 修复方案

### 1. 修复 virtualCurrentIndex 计算
- 修改 `virtualCurrentIndex` 计算属性，根据 `swiperCurrentIndex` 的位置动态计算
- 确保首次加载时显示正确的题目（索引0）

### 2. 计算真实题目索引
- 在虚拟列表渲染时，为每个项目计算真实的题目索引
- 使用真实索引而不是虚拟列表的相对索引

### 3. 修复题型组件绑定
- 更新所有题型组件的 `:question-index` 绑定，使用真实题目索引
- 修复案例题的 `:is-last-question` 判断逻辑

### 4. 优化虚拟列表边界处理
- 确保在列表开头和结尾时也能正确计算虚拟列表的当前位置

## 具体修改

### 1. 修改 virtualCurrentIndex 计算属性
```javascript
virtualCurrentIndex() {
  if (this.swiperCurrentIndex === 0) {
    return 0;
  } else if (this.swiperCurrentIndex === this.swiperList.length - 1) {
    return this.virtualSwiperList.length - 1;
  }
  return 1;
}
```

### 2. 计算真实题目索引
```javascript
// 在 v-for 中添加真实索引计算
v-for="(item, virtualIndex) in virtualSwiperList"
// 计算真实索引
:real-index="swiperCurrentIndex + (virtualIndex - virtualCurrentIndex)"
```

### 3. 修复题型组件绑定
```javascript
// 单选题
<radio-option 
  v-if="item.exam_type === 1"
  :question="item"
  :question-index="realIndex"
  ...
/>

// 案例题
<compound-option 
  v-if="item.exam_type === 6"
  :question="item"
  :question-index="realIndex"
  :is-last-question="realIndex === swiperList.length - 1"
  ...
/>
```

## 预期效果

通过以上修复，预期可以解决以下问题：
- 首次进入时正确显示第一题（序号1）
- 切换下一题时题目序号正确更新
- 进度条与显示的题目序号保持一致
- 虚拟列表在边界情况下也能正确工作

修复将集中在虚拟列表的索引计算和题型组件的属性绑定上，确保题目序号显示的准确性和一致性。
