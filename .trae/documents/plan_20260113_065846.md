### 修正后的数据库表设计方案

根据用户反馈和项目特征，重新设计数据库表，考虑租户隔离、时间戳类型和正确的表名：

#### 1. 应用版本更新表 (`article_version_update`)

**功能**：存储应用的所有版本更新记录

**表结构**：
| 字段名 | 数据类型 | 长度 | 约束 | 描述 |
|--------|----------|------|------|------|
| id | int | 11 | PRIMARY KEY AUTO_INCREMENT | 主键ID |
| tenant_id | int | 11 | NOT NULL | 租户ID（用于租户隔离） |
| version | varchar | 20 | NOT NULL | 版本号（如 v0.0.1） |
| info | text | - | NOT NULL | 更新内容 |
| time | int | 11 | NOT NULL | 更新时间戳 |
| status | tinyint | 1 | NOT NULL DEFAULT 1 | 状态（1：已发布，0：未发布） |
| create_time | int | 11 | NOT NULL DEFAULT CURRENT_TIMESTAMP | 创建时间戳 |
| update_time | int | 11 | NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间戳 |

**索引**：
- PRIMARY KEY: id
- INDEX: tenant_id (用于租户隔离查询)
- INDEX: time (用于按时间排序查询)
- INDEX: status (用于过滤已发布版本)

#### 2. 用户订阅表 (`article_user_subscribe`)

**功能**：存储用户订阅版本更新的记录

**表结构**：
| 字段名 | 数据类型 | 长度 | 约束 | 描述 |
|--------|----------|------|------|------|
| id | int | 11 | PRIMARY KEY AUTO_INCREMENT | 主键ID |
| tenant_id | int | 11 | NOT NULL | 租户ID（用于租户隔离） |
| user_id | int | 11 | NOT NULL | 用户ID |
| template_type | varchar | 50 | NOT NULL | 订阅模板类型（如 app_version_update） |
| subscribe_time | int | 11 | NOT NULL DEFAULT CURRENT_TIMESTAMP | 订阅时间戳 |
| status | tinyint | 1 | NOT NULL DEFAULT 1 | 订阅状态（1：已订阅，0：已取消） |
| create_time | int | 11 | NOT NULL DEFAULT CURRENT_TIMESTAMP | 创建时间戳 |
| update_time | int | 11 | NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间戳 |

**索引**：
- PRIMARY KEY: id
- UNIQUE INDEX: tenant_id, user_id, template_type (确保同一租户下用户对同一模板只订阅一次)
- INDEX: tenant_id (用于租户隔离查询)
- INDEX: status (用于过滤有效订阅)

### 设计说明

1. **租户隔离**
   - 每个表都添加了 `tenant_id` 字段，用于区分不同租户的数据
   - 所有查询都需要带上 `tenant_id` 条件，确保数据隔离

2. **时间戳类型**
   - 所有时间字段都使用 `int(11)` 类型存储时间戳，符合项目特征
   - 便于跨时区处理和前端展示格式化

3. **表名修正**
   - 使用 `article_` 前缀，符合项目命名规范
   - 表名更准确地反映表的用途

4. **时间字段命名修正**
   - 将 `created_at` 改为 `create_time`，符合用户要求
   - 将 `updated_at` 改为 `update_time`，保持命名一致性

5. **数据完整性**
   - 添加了必要的约束，确保数据完整性
   - 为常用查询字段添加了索引，提高查询性能

### 实现步骤

1. 创建 `article_version_update` 表
2. 创建 `article_user_subscribe` 表
3. 在后端API中实现获取版本更新列表的接口，带租户ID过滤
4. 在后端API中实现用户订阅和取消订阅的接口，带租户ID处理
5. 确保前端页面的数据请求包含正确的租户信息

### 预期效果

- 支持多租户数据隔离
- 时间字段使用时间戳，便于前端处理
- 表名符合项目命名规范
- 时间字段命名符合用户要求
- 支持版本更新记录的存储和查询
- 支持用户订阅功能的实现
