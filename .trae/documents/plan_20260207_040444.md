# 优化答题卡加载题型和题号的逻辑

## 问题分析

用户询问每次打开答题卡都会加载一次题型和题号是否合理。从代码分析：

1. **当前实现**：
   - 每次打开答题卡时，都会调用 `getQuestionStructure` 方法获取题目结构信息
   - `getQuestionStructure` 方法会调用 API 获取题型和题号
   - 即使已经有 `swiperList` 数据，也会重新加载

2. **问题**：
   - 每次打开答题卡都重新加载会导致不必要的网络请求
   - 增加服务器负担
   - 影响用户体验（特别是在网络不好的情况下）

## 优化方案

1. **恢复使用 swiperList 的逻辑**：
   - 当 `swiperList` 存在且包含所有题目时，直接使用其数据构建 `simplifiedQuestionList`
   - 只有当 `swiperList` 不存在或不完整时，才调用 API 重新加载

2. **具体修改**：
   - 取消注释 `getQuestionStructure` 方法中使用 `swiperList` 的条件判断
   - 确保使用 `swiperList` 时能够正确构建包含 `uid` 和 `exam_type` 的结构
   - 保持 API 调用作为备用方案，确保功能可用性

## 预期效果

- 减少不必要的网络请求
- 提高用户体验，特别是在网络不好的情况下
- 保持功能的可靠性，当 `swiperList` 不完整时仍能正常加载
- 减轻服务器负担
